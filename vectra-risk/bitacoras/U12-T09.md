### Lo que la tarea afirma sobre el código de otras unidades y salió distinto (la regla 2 del despacho)
Se leyó cada afirmación en el código antes de escribirla en la guía. Distintas o matizadas:
1. **Punto 9, el Service del gateway.** La tarea (y `gateway-address.sh` de U01-T16) lee el Service `api-gateway` de `vectra-edge`. El repositorio solo fija la **etiqueta** `app.kubernetes.io/name: api-gateway` (`identity-edge/gateway/generated/kind/envoyproxies.yaml`, `envoyService.labels`); el nombre del Service lo pone Envoy Gateway. `vv` y el README leen la dirección por la etiqueta (`kubectl get svc -n vectra-edge -l app.kubernetes.io/name=api-gateway -o jsonpath={.items[0]...}`).
2. **Punto 9, `--add-host` con `--network host`:** que Docker lo aplique con la red del host **no está medido** (y no se midió: sin docker). La guía y el README lo dicen y dejan la línea de `/etc/hosts` como la otra vía.
3. **Punto 10, la espera hasta las 02:40 UTC.** El código no la exige para las series: `product-metrics/src/vectra_product/scheduler.py` publica `compute` tras cada ciclo incremental (`config.CYCLE_SECONDS` = 5 min) y al cambiar el día; las series del «ayer» (`compute.py`: `periods[PeriodKey("day")] = _period(*over(yesterday, yesterday))`) pueden existir desde minutos después de las 00:00 UTC de D + 1 si hubo pasada completa al arrancar. Lo que sí fija las 02:40 UTC es la herramienta (`u11.py`, `pass_deadline`: una serie ausente antes de esa hora es `no ejecutado`, después `falla`). La guía conserva las 02:40 como hora prudente y dice lo anterior (no medido en kind). El tope superior sí es del código: `Ratio.rate` no emite la razón sin denominador, así que desde las 00:00 UTC de D + 2 D4 deja de pasar.
4. **Punto 10, el proxy no se recongela:** `window_start` (`window.py`) arranca la ventana el día UTC siguiente a la reactivación; la guía dice «otro día UTC (con un lote nuevo ese día) u otro paquete»; que un lote nuevo alcance para congelar no está medido.
5. **Punto 11, D3:** el camino de la tarea (quitar el `runId` por PR, sync con prune, volver a ponerlo) sirve para repetir D3 en la **misma** verificación (mismo `runId`, Job nuevo posterior a `started_at`); el Job no lleva `ttlSecondsAfterFinished` («se poda al cambiar el runId», `rt5-demo-job.yaml`). Para una verificación nueva el paso «volver a ponerlo» no aplica.
6. **Punto 12:** `demos/journey-7-3.md` nombra `analista-2` para el presentador de D1 y la guía reserva `analista-2` para el conductor (propone `cro-2`, que ve `ruta /casos`: `routes.ts`). No se tocó el guion: `test_demos_closed_world.py` muta ese texto. Candidata.

8. **Punto 14, `oidc.py` sin formatear en `main`** (U00-T05): `make lint` fallaba antes de tocar nada; se formateó (necesario para CA-6).
