### Decisión previa: qué imagen de `keycloak-config-cli` (fuente)
Consulta al registro público (Docker Hub, `https://hub.docker.com/v2/repositories/adorsys/keycloak-config-cli/tags`) y al README de `adorsys/keycloak-config-cli` (`main`):
- El README dice: «`a.b.c-x.y.z`: keycloak-config-cli versión `a.b.c` compilada contra Keycloak `x.y.z`» y «desde la 4.0 soporta las últimas 4 versiones de Keycloak».
- Etiquetas de la 6.5.1 con la línea 26: `6.5.1-26.0.5`, `6.5.1-26.1.0` (= `6.5.1-26`) y **`6.5.1-26.5.5`** (publicada el 2026-05-22). No existe `6.5.1-26.8.x`.
- Elegida: `adorsys/keycloak-config-cli:6.5.1-26.5.5`, digest del índice `sha256:0955d98c8a341898b7aa177477edf8a1e90569ae50bbe7598141c1270b773274` (amd64 `sha256:303b5c80…`). `docker pull` por digest: `Digest: sha256:0955d98c…` — `docker inspect`: `user=65534` (corre como no-root), `entrypoint=/bin/sh -c exec java $JAVA_OPTS -jar /app/keycloak-config-cli.jar`.
- No es una parada: sí hay una imagen de la línea 26. Lo que no se pudo probar (la tarea no ejecuta nada contra el clúster) es la importación contra Keycloak 26.8.1; queda en `CANDIDATAS.md` y lo verifica el Paso 16.

### Hallazgos de la imagen real (experimentos locales con `docker run`, sin clúster ni Keycloak)
`$ bash scratchpad/U02-T19-codificador-r1/subst.sh` (el realm de kind y todas las variables definidas salvo `NOMBRE`):
```
ERROR … KeycloakConfigRunner : Error during Keycloak import: Cannot resolve variable 'env:NOMBRE' (enableSubstitutionInVariables=true).
```
- **`$(env:NOMBRE)` es un comentario del realm** (línea 3 de `realm.{kind,staging,prod}.yaml`). La sustitución es de texto sobre el archivo entero, así que rompe la importación. Es un error del realm: va a `CANDIDATAS.md`, no se corrige aquí. El Job define `NOMBRE=NOMBRE` como rodeo (con comentario) y una prueba fija que es la única variable en un comentario.
- Con `NOMBRE` definido y `CLIENT_*_JWKS={}` el siguiente error es `Cannot deserialize value of type java.lang.String from Object value (token JsonToken.START_OBJECT)`: **un JWKS sin comillas entra al YAML como mapa**. Con el valor `"{\"keys\":[]}"` (comillas JSON) el análisis pasa y el siguiente error ya es `Connection refused` (la conexión). Por eso el `ExternalSecret` de los clientes usa `{{ .<id> | toJson }}` y la bóveda guarda el JWKS tal cual. Las contraseñas sintéticas salen alfanuméricas y empiezan por letra, para que `value: $(env:SYNTH_…)` sin comillas sea una cadena.
- `IMPORT_VARSUBSTITUTION_ENABLED=true` es la variable correcta de 6.5.1 (`--import.var-substitution.enabled`, por defecto `false`; prefijo `$(` y sufijo `)` por defecto). `UNDEFINEDISERROR` es `true` por defecto; el Job lo fija explícito.
- `keytool` viene en la imagen: `scratchpad/…/truststore.sh` arma el PKCS12 con `--read-only --user 65534 --cap-drop ALL` (`Certificate was added to keystore`; `Your keystore contains 1 entry`). Es lo que hace el init container `truststore`, porque Java solo confía en su truststore.
